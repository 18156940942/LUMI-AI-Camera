# LUMI AI Camera

**一台 iPhone 上的摄影监视器 + AI 摄影助手。为 Nikon Z6 II + iPhone 15 Pro 这套组合做的个人工具。**

快门由相机按，iPhone 只负责「看」和「想」：实时监看画面、给模特具体的姿势指令、在拍摄现场实时指出肩线歪了/头顶贴边了、拍完帮你把一批照片过一遍。

> **当前状态**：✅ 已在云端 macOS 真实编译通过（Xcode 16.4，0 error），单元测试 **334 / 334 通过**（`** TEST SUCCEEDED **`，15 个测试类），未签名 ipa 已产出并通过结构校验（见 [`dist/`](dist/README.md)）。✅ **已在真机上跑起来**（iPhone 15 Pro Max / iOS 26.0：内置摄像头在 App 进程内 29.998 fps 稳定出帧，无崩溃）。❌ **「现场好不好用」仍未验证** —— 延迟、耗电、发热、采集卡实际兼容性都还是未知数。详见[「当前状态」](#当前状态完成度与限制)。

## ⚠️ 先读这一段：一个必须先说清楚的硬件结论

**iPhone 15 Pro 无法把 USB-C 采集卡当作外接摄像头打开。**

这不是「没写」或者「懒得写」，而是 Apple 的官方行为：

- Apple DTS 工程师在开发者论坛的答复：*"it is expected that iPhone 15 Pro does not support external cameras"*、*"only iPad supports external cameras"*；
- WWDC 2023 场次《Support external cameras in your iPadOS app》：*"iPads with USB-C connectors support external cameras"*；
- `AVCaptureDevice.DeviceType.external` 这个符号在 iOS 17+ 确实存在，但在 iPhone 上 `AVCaptureDevice.DiscoverySession` 永远返回空数组。

所以本项目**没有**假装这条路径可用。iPhone 上做真实监看，走这一条（延迟约 150–400ms）：

```
Nikon Z6 II ──HDMI──▶ UVC 采集卡 ──USB──▶ 电脑（运行中继脚本）──Wi-Fi──▶ iPhone
```

三条**真实**的监看路径，App 里如实标注了各自的前提条件：

| 路径 | iPhone 15 Pro | iPad（USB-C） | 延迟 | 前提 |
|---|---|---|---|---|
| A. 网络中继（MJPEG/HLS） | ✅ 可用 | ✅ 可用 | 150–400ms | 需要一台电脑跑中继脚本 |
| B. UVC 采集卡直连 | ❌ 系统不支持 | ✅ 可用 | 最低（≈1 帧） | 需 USB-C 的 iPad + iPadOS 17+ |
| C. iPhone 内置摄像头 | ✅ 可用 | ✅ 可用 | 最低 | **仅自测/备用，不是相机监看** |

完整论证过程与出处见 [`docs/01-技术可行性与风险.md`](docs/01-技术可行性与风险.md)。

## 功能一览

### 六个页面 + 1 个附加页面

| 页面 | 做什么 |
|---|---|
| **首页** | 连接状态（真实状态，不是装饰）、设备信息、实测帧率、功能入口、数据概览 |
| **实时监看** | 专业监视器布局：画面为主，参考线与控制项环绕在四周；全屏、缩放、适配、参考线、画质参数、曝光辅助 |
| **AI 姿势助手** | 12 类场景 × 7 类风格 × 4 种景别筛选，32 条离线姿势，每条都有分步动作分解与收藏 |
| **实时姿势指导** | 在真实画面上叠加关键点与骨架，给出带实测角度的具体建议；置信度不足时**明确说「识别不稳定」而不给结论** |
| **照片管理** | 导入你主动挑选的照片，本机分析清晰度/闭眼/构图/姿态，按日期或场景分组，收藏与筛选建议 |
| **设置** | 输入设备状态、三种连接的完整指引、参考线、显示、AI 开关、诊断入口、隐私说明、版本信息 |
| **设备自检与诊断**（附加） | 运行环境（含热状态/低电量模式/可用存储）、权限状态、视频输入实时参数与**实测**帧率、中继连通性探测、内存日志、一键复制或导出纯文本报告 |
| **AI 精修与调色**（首页入口） | 14 条预设分 4 类：画质增强 / 风格化调色 / 人像美化 / 生成式改动。前三类用确定性算法，只有生成式改动会改变画面内容。**默认关闭**，需你主动开启并填入电脑端中继地址。**入口在首页功能网格里**（点「AI 精修与调色」即可选照片、选预设），也可以在照片详情页对单张执行。 |

> **为什么多加一个诊断页面**：`os.Logger` 的内容只有 macOS 的「控制台」App 或 Xcode 才能读，而本项目的开发机是 Windows、没有 Mac。也就是说真机上一出问题，现场信息**在物理上取不出来**，使用者只能说「它不工作」。这个页面把「看得见、拿得走、能定位」补上——尤其是中继探测会把原本都表现为「黑屏」的四种原因（连不上 / 超时 / 路径错 / 连上了但没画面）拆成互不相同的结论。取不到的数值一律写「未知」，绝不补一个看上去合理的默认值。

### 需求里的 6 项核心功能，对应实现

1. **真实相机实时监看** — 三条真实输入路径；画面、连接状态、设备状态、全屏、缩放、9 种参考线、安全框、实测帧率、断线报错与重连。**没有任何一帧是预录视频或静态图。**
2. **AI 姿势推荐** — 本地 JSON 数据库驱动，32 条手工撰写的姿势，覆盖全部 12 场景 / 7 风格。每条包含身体旋转方向与角度、头部转向、下巴角度、视线落点、肩颈、双手位置、重心、双腿、环境互动、摄影师机位。**不需要网络，打开即出结果。**
3. **实时 AI 姿势指导** — Apple Vision 19 个关键点；肩线倾斜、躯干倾斜、头部偏航（估算）、头部歪斜、肘关节角度、手腕高度分带、画面位置、边缘截断。**角度全部由关键点坐标算出，不含任何随机数。** 默认关闭以省电。
4. **AI 构图分析** — 头顶留白、视线方向留白、边缘截断（含「是否切在关节上」）、三分法、景别推断（附判断依据）、背景干扰。**没检测到人时只输出一条「未检测到人物」，不给任何构图结论。** 每条结论都标注是「实测」还是「建议」。
5. **照片导入与筛选** — 系统照片选择器（你自己挑选）、预览、真实 EXIF、收藏、应用内删除、按日期/场景分组、清晰度+闭眼+构图+姿态综合筛选建议。**永远不会删除或修改你相册里的原图。**
6. **摄影工具** — 三分线、九宫格、中心十字、中心参考线、水平参考线、安全框、画面比例、曝光辅助、拍摄笔记、姿势收藏、场景预设（全部可独立开关）。

## 快速开始（无 Mac，Windows 也能走完）

### 第 0 步：在电脑上自检（不需要 Mac）

```bash
python scripts/preflight.py
```

它会检查：姿势库 JSON 与 Swift 枚举是否一一对应、Xcode 工程结构是否完整（含按 OpenStep 文法**真实解析** `project.pbxproj`，而不是正则近似）、所有源码是否都挂进了 build phase、源码交叉引用的类型是否真实存在、`Hashable` 协议能否被合成、`init` 是否漏赋值、以及 **SwiftUI 观察链是否完整**（View 读了某个 Store 却没订阅它 —— 这类缺陷能编译、能过单元测试，只有真机点一下才暴露）。**9 项全绿再往下走**，能省掉大量「云端编译失败但不知道为什么」的时间。

### 第 1 步：推送到 GitHub，让云端 Mac 编译

```bash
git init
git add .
git commit -m "LUMI AI Camera"
git branch -M main
git remote add origin https://github.com/<你的用户名>/lumi-ai-camera.git
git push -u origin main
```

推送后打开仓库的 **Actions** 标签页，`Build unsigned IPA` 会自动开始运行。跑完在页面底部的 **Artifacts** 里下载 `LUMI-unsigned-ipa`。

> **这一步其实可以跳过**：本包已经附上一份**已在云端真实构建出来的 ipa** —— `dist/LUMI-unsigned-1.0.0-34.ipa`（来源、SHA-256 校验值、包结构见 [`dist/README.md`](dist/README.md)）。除非你改动了代码，否则不必自己再跑一遍 CI。

> 想在本地 Mac 上编译也可以：`xcodebuild archive -project LUMI.xcodeproj -scheme LUMI -configuration Release -sdk iphoneos -destination 'generic/platform=iOS' -archivePath build/LUMI.xcarchive CODE_SIGNING_ALLOWED=NO`

详细步骤（含失败排查）见 [`docs/02-构建与安装指南.md`](docs/02-构建与安装指南.md)。

### 第 2 步：用免费 Apple ID 装到 iPhone

未签名的 ipa 需要一个自签工具。推荐 **SideStore**（支持 Wi-Fi 续签，不用每 7 天连电脑）：

1. 在 iPhone 上安装 SideStore 或 AltStore；
2. 把下载的 `.ipa` 传进自签工具，用你的 Apple ID 签名；
3. 装完首次打开若提示「不受信任的开发者」，去 **设置 → 通用 → VPN与设备管理** 里信任你的开发者证书。

**免费 Apple ID 的现实约束**：签名有效期 7 天、同时最多 3 个自签 App、无法使用推送与部分后台能力（LUMI 不需要这些）。到期后在自签工具里**重新签一次同一个 ipa** 就行 —— 不需要重跑 CI，也不需要改任何代码。

### 第 3 步：接通相机（iPhone 路径）

1. HDMI 线从 Z6 II 的 **HDMI OUT**（mini-HDMI Type C）接到采集卡的 HDMI IN；
2. 采集卡 USB 插电脑；
3. 电脑上装依赖并启动中继：

   ```bash
   pip install opencv-python
   python tools/lumi_mjpeg_server.py --list                 # 先确认设备序号
   python tools/lumi_mjpeg_server.py --device 0 --width 1920 --height 1080 --fps 30
   ```

   脚本会打印形如 `http://192.168.1.10:8090/stream` 的地址；
4. 先在电脑浏览器打开 `http://127.0.0.1:8090` 确认画面正常；
5. 打开 LUMI → **实时监看** → **输入** → **网络中继**，填入上面的地址。

相机端的推荐设置（Nikon 官方建议的做法）：

| 菜单项 | 设为 | 为什么 |
|---|---|---|
| HDMI → 输出分辨率 | Auto | 让采集卡协商它支持的分辨率 |
| HDMI → 输出显示尺寸 | 100% | 100% 才是干净的全画幅输出 |
| HDMI → 实时取景信息显示 | 关闭 | 否则画面上会带相机的对焦框和参数叠加 |
| 自定义设定 → 待机定时器 | 无限 | 否则相机待机后 HDMI 会掉，监看中断 |

相机**不支持** HDMI 输出的情况（别在这上面浪费时间）：1080/120p、1080/100p、慢动作模式、以及 Movie 模式同时连接 Camera Control Pro 2 时。

细节见 [`docs/03-硬件连接与监看指南.md`](docs/03-硬件连接与监看指南.md)。

## 这个项目在「不造假」上的具体做法

需求里最重的一条是「不要把理论上可能实现的功能描述成已经实现的功能」。落到代码里是这样：

| 场景 | 做法 |
|---|---|
| iPhone 上点 UVC 直连 | **在尝试之前**就置为「不支持」状态，直接说明原因并列出替代方案，而不是让用户插上线等一个永远不来的设备 |
| 没有检测到人体 | 构图分析与姿势指导各只输出一条「未检测到人物」，**不产生任何角度或构图结论** |
| 关键点置信度不足 | 只输出「关键点识别不稳定，暂不给角度结论」并列出识别不到的关节名，不给近似值 |
| 骨架绘制 | `BodyPose` 为空时**一条线都不画**；关键点按置信度降低不透明度与尺寸 |
| 头部偏航 | 单目 2D 关键点推不出真正的 3D 姿态，UI 上一律标注「估算」，且置信度打 0.8 折 |
| 闭眼检测 | 明确标注为「启发式」，阈值写在代码里，建议文案要求人工确认后再剔除 |
| 曝光辅助 | 三种输入都拿不到相机机身测光值，界面上直接写明**本 App 不提供相机曝光参数**，只给画面像素的亮度分布 |
| 背景细节密度 | 实时逐帧算会很耗电，所以实时模式**明确说「本项不给结论」**，只在照片分析里给出真实数值 |
| EXIF | 读不到就是 `nil`，UI 显示「未提供」；**绝不填默认机型或默认光圈** |
| 云端 AI / API 密钥 | 本项目**完全没有云端调用，也没有任何 API 密钥**，自然不存在密钥泄漏问题 |
| 照片删除 | 只删除 App 沙盒里的副本，删除前的确认框里明确写着「相册中的原始照片不会被删除」 |
| 相机存储卡 | App 无法读取相机存储卡，这一点在照片页的边界说明里写清楚了，并给出三种把照片弄进 iPhone 的方式 |

## 项目里最容易被忽略但很关键的两处设计

**1. 姿势库存的是参数，不是文案。**

`pose_library.json` 里每条姿势存的是结构化参数（`bodyRotation: {degrees: 30, direction: left}`），具体指导语句由 `PoseScriptWriter` 统一生成。好处是**角度数值和文字描述永远一致**——不可能出现「参数写 30°、文案写 45°」的矛盾。想改文案措辞，改一个生成函数即可；想加姿势，往 JSON 里加一条即可。

**2. Xcode 工程文件是脚本生成的，不是手写的。**

`project.pbxproj` 是 Xcode 的私有格式，每条记录靠 24 位 UUID 互相引用。手改的典型后果是「新增一个 .swift 忘了登记 → 编译报错但指不到病根」。

```bash
python scripts/generate_xcodeproj.py    # 重新生成（新增/删除文件后跑一次）
python scripts/validate_project.py      # 校验 UUID 引用完整性、Sources/Resources 覆盖度
```

UUID 由「类型前缀 + 相对路径」的 MD5 推出，是确定性的：同一路径永远得到同一 UUID，所以重复运行不产生 diff，也不会撞号。

**已经真实跑过了**：`Executed 334 tests, with 0 failures` → `** TEST SUCCEEDED **`（Xcode 16.4 / iOS 18.5 模拟器，见 [run #38235197624](https://github.com/18156940942/LUMI-AI-Camera/actions/runs/38235197624)）。


16 个测试文件（15 个测试类、**334 个用例**）覆盖的都是**能用数字断言的逻辑**，不是「跑通即可」：

- 几何方向约定（Vision 原点左下 vs SwiftUI 原点左上，搞反了 UI 上很难发现）
- 推荐引擎打分（权重、排序稳定性、场景不匹配时不清空结果）
- 姿势文案与参数的一致性（改参数文案必须跟着变）
- 构图阈值边界（2% / 5% / 35% 头顶留白、三分线容差）
- **门控行为**：低置信度必须闭嘴、没人物必须不给结论
- 画质指标（纯色图方差必须为 0、棋盘格必须高、归一化必须钳制在 0…1）
- EXIF（真实 JPEG 往返、缺字段必须是 nil）
- 姿势库数据库体检（32 条、12 场景 7 风格全覆盖、枚举值合法、角度在人体可执行范围）
- **诊断模块**（日志环形缓冲的容量与淘汰顺序、级别标签完备性、字节格式化的四个单位边界、报告拼装的时区确定性、滚动帧率的四个退化边界）

- 摄像头权限：**仅**在「内置摄像头」模式用到，且不会自动启动，必须你手动点；

| 6 | —— | **全绿**（252 个用例） |
| 7 | 未报错，但**审查诊断页要显示的数据时发现** | `analysisFPS` 的分母两个分支都取到 0，实际算成了「累计帧数 ÷ 开机时长」→ 恒为 0.0。界面上有个指标，数值一直是废数 |

前 4 个是我写代码时的真实疏漏；第 5 个是产品代码的浮点边界问题（**不是测试写错**，我改的是产品代码）；第 7 个是**测试抓不到的**——它不是崩溃也不是异常，只是算出了一个合法但无意义的数。修完后我把这些错误类型做成了静态检查项补进 `preflight`，让它们变成不会再犯的类别 —— 逐轮根因见 [`docs/04`](docs/04-功能完成度与已知限制.md#编译是怎么完成的)。

## 关于姿势库

姿势库是**纯数据**的，你完全可以自己往里加：

```jsonc
// LUMI/Resources/pose_library.json
{
  "version": 1,
  "poses": [
    {
      "id": "outdoor-05",                       // 唯一即可
      "name": "斜阳下的侧身回眸",
      "summary": "用长焦压缩背景，让人物从环境里跳出来",
      "scenes": ["outdoorPortrait", "lookingBack"],   // 必须是用 PoseTypes.swift 里的枚举原始值
      "styles": ["gentleHealing"],
      "shotType": "halfBody",
      "bodyRotation": { "degrees": 40, "direction": "left" },
      "headTurn":     { "degrees": 70, "direction": "right" },
      "chin": "up5",
      "gaze": { "anchor": "overShoulder", "detail": "越过肩膀看向远处树梢" },
      "shoulders": "backHigher",
      "nearestHand": "inHair",
      "otherHand": "relaxedDown",
      "weight": "backLeg",
      "legs": "oneFootForward",
      "environment": "找有明暗交界的树影，让人物站在亮处",
      "cameraAngle": "eyeLevel",
      "composition": {
        "horizontalAnchor": 0.35, "headAnchor": 0.22,
        "headroomRatio": 0.1, "needsLeadRoom": true,
        "note": "视线方向留出比背后更多的空间"
      },
      "photographerTips": "先让模特站定、把头发拨松，再让她慢慢回头；转头速度要慢，抓最慢的那一下",
      "difficulty": 2,
      "keywords": ["回眸", "侧身", "长焦"]
    }
  ]
}
```

改完**务必**跑一次预检，它会告诉你有没有写错枚举值：

```bash
python scripts/preflight.py
```

（这个检查是必要的：JSON 里一个枚举值写错，运行时只会得到一句「姿势库解析失败」，很难定位。项目开发过程中就真的踩到过。）
