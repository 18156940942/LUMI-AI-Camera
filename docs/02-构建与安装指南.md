# 构建与安装指南（没有 Mac 也能走完）

本文档面向的是这个项目的真实处境：**手上只有 iPhone 和一台 Windows 电脑，没有 Mac，只有一个免费 Apple 账号，不想上架 App Store。**

整条链路是：

```
Windows 电脑                        GitHub 云端 macOS                iPhone
──────────────                     ─────────────────                ──────
① 跑预检脚本                       ② 自动编译 + 跑测试
   确认工程结构没问题       ──▶       产出未签名 ipa         ──▶   ③ 用 SideStore
                                                                    + 免费 Apple ID
                                                                    自签安装
```

---

## 0. 为什么需要绕这么大一圈

三个客观限制决定了这条路径：

1. **编译 iOS App 必须用 macOS + Xcode。** 没有任何 Windows/Linux 上的替代方案，这是 Apple 的工具链限制，不是可以绕开的配置问题。
2. **免费 Apple 账号不能生成能上架的签名。** 免费账号的签名有效期只有 7 天，同时最多签 3 个 App，且需要「自签工具」在设备侧完成签名 —— 这正是 SideStore / AltStore 存在的原因。
3. **免费账号无法使用 Cloud 签名证书。** 所以必须走「未签名 ipa + 设备侧自签」这条路，而不是 `xcodebuild -exportArchive`。

GitHub 对公开仓库提供**免费的 macOS 运行器**，这就是第 1 步的解法。

---

## 1. 第一步：在 Windows 上做工程自检

**不要跳过这一步。** 云端编译一次要等好几分钟，而下面这些检查只要几秒钟：

```bash
cd LUMI-AI-Camera
python scripts/preflight.py
```

它会做四件事：

| 检查 | 抓什么问题 |
|---|---|
| 姿势库 JSON ↔ Swift 枚举交叉校验 | JSON 里写错一个枚举值（例如 `"tiltRightDown"`），运行时只会得到「姿势库解析失败」，在 Mac 上极难定位 |
| Xcode 工程文件结构校验 | UUID 引用缺失（工程直接打不开）、有文件没挂进 Sources 阶段（报 `cannot find 'Xxx' in scope`）、资源没进 Resources 阶段（运行时读不到姿势库） |
| Swift 源码交叉引用 | 测试或视图里引用了不存在的类型名（拼写错误） |
| 资料完整性 | id 重复、场景/风格覆盖不全、难度越界、旋转方向与角度自相矛盾 |

期望输出：

```
全部 7 项通过。可以推送到 GitHub 触发云端 macOS 构建了。
```

如果没通过，它会明确告诉你是哪个文件的哪一条数据有问题。

> 如果你在项目里新增或删除了 `.swift` 文件，先跑一次 `python scripts/generate_xcodeproj.py` 重新生成工程文件，再跑预检。

## 2. 第二步：推到 GitHub，让云端 Mac 编译

### 2.1 建仓库并推送

```bash
git init
git add .
git commit -m "LUMI AI Camera: initial commit"
git branch -M main
git remote add origin https://github.com/<你的用户名>/lumi-ai-camera.git
git push -u origin main
```

### 2.2 观察构建

推送完成后：

1. 打开仓库页面 → 顶部 **Actions** 标签；
2. 左侧会看到 `Build unsigned IPA`，点进去能看到本次运行；
3. 整条流水线有两个任务：

   - **工程自检**（跑在 Ubuntu 上，几秒钟）—— 就是第 1 步那个预检脚本，放在 CI 里当门槛；
   - **编译未签名 ipa**（跑在 macOS 上，通常 5–12 分钟）—— 依次做：选模拟器 → 跑单元测试 → 归档 → 打包 ipa → 校验 ipa 结构。

4. 跑完后，在运行页面底部的 **Artifacts** 区域下载：

   - `LUMI-unsigned-ipa` ← **这就是你要的东西**
   - `LUMI-build-logs` ← 测试日志与归档日志，构建失败时看这个

### 2.3 流水线到底做了什么（了解原理能省下大量排查时间）

```bash
# ① 跑单元测试（不过就不出包）
xcodebuild test \
  -project LUMI.xcodeproj -scheme LUMI \
  -destination "id=<动态选出的模拟器 UDID>" \
  CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY="" \
  PROVISIONING_PROFILE_SPECIFIER="" DEVELOPMENT_TEAM=""

# ② 归档。注意：这里必须把签名全部关掉
xcodebuild archive \
  -project LUMI.xcodeproj -scheme LUMI \
  -configuration Release -sdk iphoneos \
  -destination "generic/platform=iOS" \
  -archivePath build/LUMI.xcarchive \
  CODE_SIGNING_ALLOWED=NO \
  CODE_SIGN_IDENTITY="" \
  CODE_SIGNING_REQUIRED=NO \
  PROVISIONING_PROFILE_SPECIFIER="" \
  DEVELOPMENT_TEAM=""

# ③ 手工组装 ipa。为什么不用 -exportArchive？
#    因为导出归档必须有签名证书，免费账号提供不了。
#    未签名 ipa 的标准做法就是手工拼一个 Payload 目录再 zip：
mkdir -p build/Payload
cp -R build/LUMI.xcarchive/Products/Applications/LUMI.app build/Payload/
cd build && zip -qry LUMI-unsigned.ipa Payload
```

ipa 的本质就是一个 zip，里面只有一个 `Payload/` 目录，`Payload/` 里是 `LUMI.app`。所以手工打包是完全等价且可控的。

**四个签名参数必须同时给全。** 只给 `CODE_SIGNING_ALLOWED=NO` 有时仍会因为 provisioning profile 缺失而失败，把 `CODE_SIGN_IDENTITY`、`PROVISIONING_PROFILE_SPECIFIER`、`DEVELOPMENT_TEAM` 都清空最稳。

### 2.4 在本地 Mac 上编译

如果你借得到一台 Mac（哪怕只装 Xcode，没有开发者账号）：

```bash
# 直接在 Xcode 里打开工程
open LUMI.xcodeproj
```

首次打开需要在 **Signing & Capabilities** 里把你的 Apple ID 加进 **Team**，然后连上 iPhone 按 ⌘R 直接跑（这就是最省事的路径，不需要 ipa、不需要自签工具）。

命令行方式：

```bash
xcodebuild archive \
  -project LUMI.xcodeproj -scheme LUMI \
  -configuration Release -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  -archivePath build/LUMI.xcarchive \
  CODE_SIGNING_ALLOWED=NO
```

> 注意：`xcodebuild` 需要命令行工具。在 Xcode 里跑一次 `xcodebuild -runFirstLaunch` 即可。

## 3. 第三步：用免费 Apple ID 装到 iPhone

### 3.1 选一个自签工具

| 工具 | 优点 | 缺点 |
|---|---|---|
| **SideStore**（推荐） | 通过 Wi-Fi 自动续签，不用每 7 天连电脑；开源 | 初次配置稍麻烦，需要一个配对文件 |
| **AltStore** | 配置简单，生态成熟 | 续签需要电脑在同一个 Wi-Fi 且 AltServer 在运行 |
| **Sideloadly** | Windows 上直接可用，不挑环境 | 每次续签都要插线，适合「先跑起来看看」 |

**如果你只是想先验证一下能不能装、能不能用，用 Sideloadly 最快**：Windows 上装好、插线、拖 ipa、输 Apple ID，五分钟搞定。

**如果你想长期用（这个 App 是给你拍照时用的，一定会长期用），装 SideStore。**

### 3.2 安装步骤（以 SideStore 为例）

1. **在 iPhone 上安装 SideStore**：官网提供了详细步骤，核心是用一个「配对文件」让它能在设备上自行完成续签；
2. **把 ipa 传到 iPhone**：AirDrop、iCloud 云盘、或者发给自己微信文件传输助手都行；
3. **在 SideStore 里导入 ipa**，用你的 Apple ID 登录并签名；
4. **首次打开 App 会提示「不受信任的开发者」** —— 这是正常的，去：
   **设置 → 通用 → VPN与设备管理 → 开发者 App → 选择你的 Apple ID → 信任**
5. 打开 LUMI，看到隐私说明页，说明装成功了。

### 3.3 关于免费账号的现实约束

| 约束 | 影响 | 应对 |
|---|---|---|
| 签名有效期 **7 天** | 7 天后 App 打不开（图标变灰或点击闪退） | SideStore 会在后台自动续签；AltStore 需要电脑开着 AltServer |
| 最多 3 个自签 App | 不能无限装 | 只留这个 App，或删掉不用的 |
| 无法使用 Push 通知 | — | LUMI 不需要 |
| 无后台长时间运行权限 | — | LUMI 的监看是前台行为，不需要 |
| Bundle ID 不能重复 | 如果同一个 Apple ID 装过同名 bundle 的其他 App | 改 `project.pbxproj` 里的 `PRODUCT_BUNDLE_IDENTIFIER`（或改 `scripts/generate_xcodeproj.py` 里的 `BUNDLE_ID` 后重新生成） |

### 3.4 续签：7 天到期怎么办

**用 SideStore**：它会在到期前通过 Wi-Fi 自动续签，通常你不需要做任何事。如果自动续签失败（比如换了 Wi-Fi、iPhone 重启后 SideStore 没被打开过），打开一次 SideStore 让它重跑即可。

**用 Sideloadly / AltStore**：重新运行一次 GitHub Actions 或直接用本地那份 ipa，重新签一次。ipa 不需要重新下载 —— 未签名的 ipa 本身不会过期。

## 4. 常见问题对照表

### 构建相关

| 现象 | 原因 | 处理 |
|---|---|---|
| `工程自检` 任务失败 | 姿势库数据或工程结构有问题 | 看日志里 `✗` 那一行，本机跑 `python scripts/preflight.py` 复现 |
| `error: Signing for "LUMI" requires a development team` | 签名没关干净 | 确认 archive 命令带全了四个签名参数（见 2.3） |
| `xcodebuild: error: Unable to find a destination matching...` | 硬编码的模拟器型号在 runner 镜像里不存在 | 本项目已用 `scripts/pick_simulator.py` 动态挑选，正常情况下不会出现 |
| `Cannot find 'XXX' in scope` | 有 `.swift` 文件没被加进 Sources 阶段 | 本机跑 `python scripts/generate_xcodeproj.py` 重新生成工程，再推送 |
| `The project cannot be opened because it is in a future Xcode project file format` | 工程文件版本太新 | 本项目使用 `objectVersion = 56`（Xcode 14+ 格式），Xcode 15/16 都能打开 |
| 测试失败 | 真实逻辑 bug | 看 `LUMI-build-logs` 里的 `test.log`，里面有失败用例名与断言详情 |
| macOS 构建排队很久 | GitHub 免费额度共享队列 | 正常，等即可；可以把 `push` 触发只保留 `main` 分支减少排队 |

### 安装相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 装完点不开，或提示「无法安装此 App」 | 签名无效 / 证书被撤销 | 删除 App，重新自签 |
| 用了一周后突然打不开 | 7 天签名到期 | 重新续签（见 3.4） |
| 「不受信任的开发者」 | 新签名的证书设备还没信任 | 设置 → 通用 → VPN与设备管理 → 信任 |
| SideStore 里签名报错 `The bundle identifier is not available` | 这个 bundle id 已被同账号的其他 App 占用 | 改 bundle id（见 3.3 表格最后一行） |
| App 里点「内置摄像头」没反应 | 没给相机权限 | 设置 → 隐私与安全性 → 相机 → 打开 LUMI |

### 使用时

| 现象 | 原因 | 处理 |
|---|---|---|
| 「实时监看」里选了外接 UVC 采集设备，提示不支持 | **这是预期行为**，iPhone 不支持 UVC | 用「网络中继」或「内置摄像头」，详见 [03-硬件连接与监看指南](03-硬件连接与监看指南.md) |
| 中继填了地址但连不上 | 手机和电脑不在同一 Wi-Fi / 防火墙拦了端口 | 见 03 文档的故障排查表 |
| 画面很卡或延迟很大 | Wi-Fi 带宽不够 / 分辨率太高 | 降到 720p，或用 5GHz Wi-Fi |

## 5. 在没有 Mac 的情况下，怎么保证代码质量

这是这个项目最特殊的约束。采取的措施：

1. **预检脚本替代「打开 Xcode 看一眼」**（`scripts/preflight.py`）。它检查的是编译期和运行期最容易出问题、又最难定位的三类问题：工程结构、枚举↔数据一致性、类型引用完整性。
2. **把编译和测试放进 CI 的必过门槛**。`build` 任务 `needs: preflight`，且测试不过就不出包。所以第一次推送就能拿到真实的编译错误清单，而不是「看起来写完了」。
3. **单元测试只写能用数字断言的逻辑**。姿态几何、推荐打分、阈值边界、门控行为、像素指标、EXIF 解析 —— 这些都是「错了会安静地给出错误结果」的地方，必须有断言守着。UI 布局之类没法自动验证的不强求。
4. **文档里如实标注未验证项**。见 [04-功能完成度与已知限制](04-功能完成度与已知限制.md)。

**必须承认的是**：这份代码从未被编译过。如果你在 CI 里看到编译错误，那是预期内的 —— 那是这类开发方式不可避免的成本，而不是「应该早就发现」的疏漏。看到错误后把日志贴出来即可定位修复。
