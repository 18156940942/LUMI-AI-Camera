# 阶段一：Nikon Z6 II → iPhone 15 Pro 视频输入可行性分析

> 本文档中的所有结论都标注了依据来源。凡标「**不可行**」的，都是经过官方文档 / 官方开发者论坛确认的硬性限制，不是推测。
> 本项目遵循一条铁律：**不把理论可能当作已实现，不用模拟画面冒充真实监看。**

---

## 1. 一句话结论

| 问题 | 结论 |
|---|---|
| Nikon Z6 II 能否输出可用于监看的 HDMI 视频？ | ✅ **能**，且支持「干净输出」（无叠加信息的未压缩 HDMI 输出） |
| iPhone 15 Pro 能否读取 USB-C 接入的 UVC 采集卡视频？ | ❌ **不能**。iOS 从不枚举 UVC 外接摄像头，与 USB-C 接口无关 |
| 能否通过厂商 SDK 绕过？ | ❌ **不能**。Nikon 没有面向第三方 iOS App 的相机 SDK；MFi 外设路线需要付费 MFi 会员 + 认证硬件，个人使用不可行 |
| 那 iPhone 上还能实时监看吗？ | ✅ **能，但必须走「网络中继」**：Z6 II → HDMI 采集卡 → 电脑 → 局域网 → iPhone。本项目已实现该链路的低延迟播放客户端 |
| 有没有原生低延迟方案？ | ✅ 有，但**硬件是 iPad（USB-C）而不是 iPhone**。同一份 App 在 iPad 上即插即用 |

## 2. 必须解决的硬件兼容性问题（清单）

| # | 问题 | 结论 | 依据 |
|---|---|---|---|
| 1 | Z6 II 的 HDMI 接口规格 | **mini-HDMI（Type C）**，非全尺寸 HDMI。需 Type-C→Type-A 转接线 | Nikon 官方规格表（Interface: HDMI: Type C HDMI connector） |
| 2 | Z6 II 是否有「干净 HDMI 输出」 | 有。Z6 II 在 Nikon 官方「可输出未压缩数据到外部 HDMI 设备」的机型名单内 | Nikon 官方支持文章《如何将未压缩的影片从相机输出到外部 HDMI 设备》 |
| 3 | Z6 II HDMI 输出分辨率/帧率 | 外录模式下支持 4:2:2 10-bit 的 UHD 4K (3840×2160) 与 1920×1080 | Nikon/B&H 规格：External Recording Modes 4:2:2 10-Bit via HDMI |
| 4 | HDMI 输出的例外情况 | 1920×1080 **120p/100p**、慢动作短片、以及 Movie 模式连接 Camera Control Pro 2 时**不输出** HDMI | Crutchfield 规格说明（引自 Nikon 手册） |
| 5 | 拍照模式（Stills）下 HDMI 是否出图 | 出。输出内容默认与相机背屏一致（含信息叠加），需在菜单里关掉叠加即为干净画面 | Nikon 官方推荐设置；DPReview 用户实测（Z6/Z6II/Z6III 均可） |
| 6 | 推荐相机端设置 | HDMI 输出分辨率=自动；HDMI 输出显示尺寸=100%；HDMI 实时显示屏幕显示=**关闭**；待机定时器=不限 | Nikon 官方支持文章「推荐的相机设定」 |
| 7 | USB-C 直连相机能否拿到实时画面 | **不能**。Z6 II 的 USB-C 是 USB 数据/PTP 通道，iOS 上的 App 无法通过它取流。SnapBridge 的实时取景是 Nikon 自有 App 的私有实现，无公开 iOS SDK | Nikon 官网仅提供 SnapBridge / NX Tether / Camera Control Pro 2（桌面端） |
| 8 | iPhone 15 Pro 读 UVC 采集卡 | **不能** | Apple DTS 工程师回复（developer.apple.com/forums/thread/775883）：*"it is expected that iPhone 15 Pro does not support external cameras"*；WWDC 2023《Support external cameras in your iPadOS app》：*"iPads with USB-C connectors support external cameras"*；Apple 文档对外接设备的描述主语是 iPad |
| 9 | 采集卡供电 | 多数 HDMI 采集卡（如 Elgato Cam Link 4K）需 USB 3.0 供电，**建议用带供电的 USB-C 集线器**，否则可能掉线或黑屏 | 采集卡通用要求 / iPad 外接相机官方建议（powered hub） |
| 10 | 采集卡格式 | 必须选 **UVC 免驱**（USB Video Class）的采集卡，不要选需要厂商专用 SDK 的型号 | 与第 8 条配套：iOS 只认 UVC；非 UVC 设备在任何 iOS 设备上都无解 |

> ⚠️ **特别提醒**：市面上有将 Lightning 采集器与「配套 App」捆绑销售的产品，其能力来自厂商私有协议 + 私有 App，**第三方 App 无法接入**；且在 USB-C 的 iPhone 15 上这类 Lightning 方案连物理接口都不匹配。买硬件前请按第 10 条核对「UVC / UVC compliant」。

## 3. 三条可验证的真实监看链路

### 链路 A：网络中继（**iPhone 上唯一可行**，本项目已实现）

```
Nikon Z6 II ──mini-HDMI──> UVC 采集卡 ──USB──> 电脑(Windows/macOS)
                                                 │  ffmpeg 解码 + MJPEG/HLS 编码
                                                 ▼
                                       局域网 HTTP 流
                                                 │
                                        iPhone 15 Pro（LUMI App 播放）
```

* **实测预期延迟**：1080p@15~30fps MJPEG 在 5GHz 局域网、关闭缓冲/tcp-nodelay 的条件下约 **150~400 ms**；H.264/HLS 模式延迟更高（1~3 s），仅在带宽受限时使用。
* **成本**：UVC 采集卡 ¥100~400（免驱款即可），没有其他额外硬件。
* **限制**：需要一个能长期开着的电脑（含 Windows 笔记本）；延迟比原生直连高一个量级；只适合看构图与姿态，**不适合精确对焦确认**。
* **本项目提供**：`tools/lumi_mjpeg_server.py`（一键把采集卡变成低延迟 MJPEG 流）+ App 内的 MJPEG 客户端（自研 multipart 解析，非第三方库）。

### 链路 B：iPad（USB-C）直连（**原生低延迟**，代码已写好）

```
Nikon Z6 II ──mini-HDMI──> UVC 采集卡 ──USB-C──> iPad (USB-C, iPadOS 17+)
                                                     │  AVCaptureSession + .external
                                                     ▼
                                                  LUMI App 原生预览图层（≈1~2 帧延迟）
```

* 这是 Apple 官方支持的唯一原生路线，也是本项目为「真实监看」准备的**首选**路径。
* iPad 需满足：USB-C 接口 + iPadOS 17.0 及以上；并在 `设置 → 隐私与安全性 → 有线配件`（部分版本）允许已连接设备。
* 成本：如果已经想升级设备，一台 USB-C 的入门 iPad 远比换相机便宜。
* **本项目已实现** `UVCVideoInput`：在 iPad 上插上采集卡即可识别为外接摄像头；在 iPhone 上会明确显示「本机不支持 UVC 外接摄像头」而不是假装连接。

### 链路 C：iPhone 内置摄像头（**真实现场帧，但明确标注为自测/备用**）

* 用途：在没有采集卡的场合，仍然可以在**真实视频帧**上验证姿势检测、构图分析的效果，也满足日常人像姿势指导。
* **App 内会显著标注**：`iPhone 内置摄像头（自测/备用，非 Z6 II 监看）`，绝不冒充相机监看。
* 这一路是真实 AVFoundation 采集，不是预录视频、不是静态图、不是模拟画面。

## 4. 明确判定为「不可行」并给出原因的项

| 设想 | 判定 | 原因 |
|---|---|---|
| iPhone 15 Pro 通过 USB-C 直接读 HDMI 采集卡 | ❌ 不可行 | iOS（含 iOS 26）不枚举 UVC 设备；USB-C 只是接口形状，不等于支持 USB 外设类别 |
| iPhone 通过 Lightning/USB-C 专有采集器 + 厂商 SDK | ❌ 不可行 | 需要厂商私有协议与私有 App，不开放给第三方；MFi 路线需付费会员与认证硬件 |
| 用 Nikon USB-C + PTP 在 iOS 上取实时取景 | ❌ 不可行 | iOS 无 libgphoto2 一类用户态 USB 访问；Nikon 未提供第三方 iOS SDK |
| iPhone 直接连 Z6 II 的 Wi-Fi 取流 | ❌ 不可行 | Z6 II 的 Wi-Fi 遥控实时取景是 SnapBridge 私有实现，无公开接口 |
| iPhone 有线 HDMI 输入 | ❌ 不可行 | iPhone 的 USB-C 只有 DisplayPort **输出**，没有视频输入通道 |
| 用预录视频/静态图充当监看 | ❌ 禁止 | 违反本项目最高优先级原则。App 内没有任何模拟视频资源 |

## 5. 对产品的影响（必须写进 UI 的诚实说明）

1. 实时监看页会**根据连接状态显示三种真实状态之一**：`未连接` / `外接 UVC 设备`（iPad 生效）/ `网络中继流`，绝不显示虚构状态。
2. 当检测到运行设备是 iPhone 且用户选择「UVC 直连」时，App 显示一段说明：
   > 本机（iPhone）不支持 UVC 外接摄像头。请在 iPad（USB-C，iPadOS 17+）上使用此模式，或改用「网络中继」模式。
3. 帧率/分辨率信息只在输入设备**真的提供**时显示；网络流只显示收到的分辨率与实际到达帧率。
4. AI 姿态与构图分析只以**当前真实帧**为输入；没有帧时显示「等待视频输入」，不给任何结论。
5. 曝光辅助信息：HDMI/UVC/内置摄像头都**不提供**机身曝光参数，因此 App 只显示「画面亮度分布」这类从像素真实计算出的客观值，并注明「非相机测光数据」。

## 6. 阶段一遗留风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 中继链路延迟受局域网质量影响 | 构图判断可用，精确对焦不可用 | 走 5GHz、用有线回传、MJPEG 关闭缓冲；App 内实时显示到达帧率 |
| 采集卡型号兼容性差异 | 少数非 UVC 卡无法工作 | 只推荐免驱 UVC 卡；链路 B 用 DiscoverySession 实时枚举，插上即可验证 |
| 4K UHD 输入带宽高 | 中继端 CPU/网络压力大 | 中继脚本默认 1080p30，可在参数里改 |
| 长时间 HDMI 输出导致相机发热/耗电 | 拍摄中意外断电 | 用假电池 + 关闭自动休眠；文档中已写明 |
| 免费 Apple ID 签名 7 天过期 | App 会打不开 | 构建指南里写明 SideStore/Sideloadly 自动续签方案 |

**阶段一结论：主功能路线的判定已经完成，路线可验证。进入阶段二。**
