# 照片精修管线

本文档说明「照片精修」这个功能**实际是怎么工作的**，以及它**做不到什么**。

---

## 入口在哪

- **首页 → 功能网格 → 「AI 精修与调色」**（主要入口，点进去可以选照片、选预设、看前后对比）
- 照片详情页 → 底部「精修这张照片」/「查看 · 重新精修」
- 设置页 → 「云端精修」（配置总开关与中继地址）

> 首页那张卡是**后来补的**。最初精修只挂在照片详情页的操作按钮和设置页的配置项上，
> 结果是「功能其实存在，但界面上找不到」—— 实测反馈就是
> 「在 LUMI 里并没有看到智能 AI 修图和调色功能」。
> 一个功能只有能被找到才算存在，这一条按这个标准补上。

---

## 一、先说清楚三件做不到的事

这一节的目的是让你在使用前就知道边界，而不是用了之后才发现。

### 1. 「每拍一张照片自动传过来」做不到

**App 无法让相机把照片发过来。** 它没有路径能触发 Z6 II 拍照，也没有路径能接收相机推来的文件。

照片进入 LUMI 的唯一方式是**你从系统相册手动挑选**。所以诚实的说法是：

> **你选完照片导入 LUMI 之后，精修会自动开始。** 不是「相机一拍就自动进来」。

要实现「拍完自己进来」，必须有别的东西先把照片弄到 iPhone 相册里 —— 例如 Nikon SnapBridge 的自动传输，或者 Z6 II 连电脑后由电脑推送。那是 App 之外的事。

### 2. 「实时」做不到

一张 Z6 II 全分辨率照片（约 6000×4000）走完整个流程：

| 环节 | 典型耗时 |
|---|---|
| 上传到电脑 | 局域网内 1–3 秒（24 MP JPEG 约 10–20 MB） |
| 本地算法处理 | 0.3–5 秒（取决于预设，见下表） |
| 云端生成式改动（如果用了） | 额外 5–30 秒 |

**实际是「几秒到几十秒」，不是实时。** 它的定位是「拍完一批、导进来、自动过一遍」，不是「边拍边看」。

### 3. 生成式改动的结果不确定

前三类是确定性算法：**同样的输入永远得到同样的输出**，改动范围也可预期。

「生成式改动」不是 —— 它是让模型**重绘画面内容**。同一张照片、同一句指令，两次结果可能不同；也可能改得超出你的预期。所以这一类必须逐张人工确认。

## 二、架构

```
iPhone (LUMI)                你的电脑 (中继脚本)              云端服务商
     │                              │                            │
     │── POST /retouch ────────────▶│                            │
     │   multipart:                 │                            │
     │     image / preset /         │── 需要生成式时 ───────────▶│
     │     intensity / prompt       │                            │
     │                              │◀──────── 重绘后的图 ────────│
     │◀── image/jpeg ───────────────│                            │
     │    X-Lumi-Provider           │                            │
```

**为什么密钥在电脑上而不在 App 里**：云端密钥一旦编译进 iOS 客户端就等于泄漏 —— 反编译拿字符串是常规操作。App 内的隐私说明写的也是这个做法：「把密钥放在你自己的服务端，客户端只调用你的接口」。

**手机侧只有一条代码路径**：不管是本地算还是调云端，客户端都只做「把照片发给中继、拿回图片」这一件事。这避免了在 Swift 里重写一遍图像算法。

## 三、跑起来

### 依赖

```bash
pip install opencv-python numpy
```

### 启动

```bash
# 看一眼有哪些预设
python tools/lumi_retouch_server.py --list

# 取一次人脸检测模型（只有「面部提亮」需要，约 230 KB）
python tools/lumi_retouch_server.py --fetch-face-model

# 启动（只做本地精修，不需要任何密钥）
python tools/lumi_retouch_server.py
```

脚本会打印手机侧要填的地址，形如：

```
  手机侧填这个地址（App → 设置 → 云端精修）：
      http://172.20.10.8:8091
```

**先用电脑浏览器打开 `http://127.0.0.1:8091` 自测** —— 状态页会显示本地执行器可用、云端是否已配置、人脸模型是否就绪，以及全部预设列表。

### 在 App 里配置

**设置 → 云端精修 → 开启精修功能 → 填中继地址**。

然后：**照片管理 → 点开一张照片 → 「精修这张照片」**。

### 防火墙

Windows 默认会把这类监听当作「公用网络」并拦住。手机连不上时先检查：

```powershell
# 管理员 PowerShell
New-NetFirewallRule -DisplayName "LUMI retouch 8091" `
  -Direction Inbound -Protocol TCP -LocalPort 8091 `
  -RemoteAddress LocalSubnet -Action Allow -Profile Any
```

## 四、预设清单（14 条）

### 本地执行（11 条，零密钥，照片不出本机）

| 预设 | 做什么 | 实测耗时（24 MP） |
|---|---|---|
| `enhance.auto` | 按画面统计自动决定降噪/锐化/暗部力度 | ~3.7 s |
| `enhance.denoise` | 保边平滑，**只作用于色度通道**，亮度细节保留 | ~0.3 s |
| `enhance.sharpen` | 亮度通道反锐化掩模 | ~1.3 s |
| `enhance.shadow` | 只抬暗部（权重 `(1-L)³`，纯白处不动） | ~1.7 s |
| `enhance.dehaze` | 暗通道先验去雾 | ~2 s |
| `grade.film` | 抬黑位 + 压高光 + 暗部偏青 | <1 s |
| `grade.clean` | S 形对比曲线 + 提饱和 | <1 s |
| `grade.warm` | 抬红压蓝 + 轻微抬中间调 | <1 s |
| `grade.mono` | 加权转灰 + 对比曲线 | <1 s |
| `portrait.skinSoft` | **肤色掩膜范围内**的保边柔化（保留毛孔与轮廓） | ~2 s |
| `portrait.brightenFace` | YuNet 检测人脸后只提亮脸部；**检测不到人脸就明确报错**，不会整张提亮 | ~2 s |

这些全部是**确定性像素运算**，不是「AI 猜出来的」。同样输入永远同样输出，可复现、可验证。

### 云端执行（3 条，需要你自己配置服务商）

| 预设 | 做什么 |
|---|---|
| `generative.custom` | 用文字描述想要的改动 |
| `generative.removeObject` | 去掉指定物体（在描述里写清去掉什么） |
| `generative.skyReplace` | 替换天空（在描述里写清换成什么） |

**未配置云端时，这三条会被明确拒绝**（HTTP 501，错误码 `provider_not_configured`），**不会返回原图冒充结果**。

## 五、接上你自己的云端服务商

```bash
export LUMI_CLOUD_URL="https://你的服务商/v1/images/edits"
export LUMI_CLOUD_KEY="sk-..."
export LUMI_CLOUD_MODEL="你的模型名"
```

也可以写成命令行参数 `--cloud-url / --cloud-key / --cloud-model`。

密钥只存在于你的电脑上，**不会被打印、不会进这个仓库**。

默认请求形态是 `multipart/form-data` 带 `image` / `prompt` / `model` 字段 —— 这是目前最通用的一种（OpenAI `images/edits` 就是这一形态）。

**换成别的服务商**只需要改 `tools/lumi_retouch_server.py` 里的两处：

- `CloudProvider._build_request` —— 怎么发请求
- `CloudProvider._extract_image` —— 从响应里怎么取图

`_extract_image` 已经支持三种常见形态：直接返回图片、`data[0].b64_json`、`data[0].url`。都不匹配时会明确报错并告诉你要改哪里，而不会猜。

## 六、踩过的坑（都写进代码注释了）

### 1. OpenCV 在 Windows 上读不了含中文的绝对路径

`cv2.FaceDetectorYN.create()` 读 ONNX 走的是**窄字符（ANSI）路径**。绝对路径里只要有非 ASCII（例如 `C:\Users\饭饭之叫\...`）就会失败，报 `Can't read ONNX file` —— 而文件明明存在、大小也对。

实测结论：

| 路径形式 | 结果 |
|---|---|
| `tools/models/x.onnx`（相对，纯 ASCII） | ✅ |
| `C:\Users\饭饭之叫\...\tools\models\x.onnx` | ❌ |
| `C:\ProgramData\LUMI\models\x.onnx` | ✅ |

所以脚本写了一条候选路径回退链：**绝对路径 → 相对路径 → 拷到纯 ASCII 目录**。不处理的话，「面部提亮」在中文用户名的机器上必然不可用。

### 2. 暗通道去雾的两个数组错误

- 写了 `max(atmosphere, 1.0)`，而 `atmosphere` 是长度为 3 的数组 —— Python 内置 `max()` 会去比较数组的真值，直接抛 `ValueError`。
- 修掉之后立刻撞上第二个：暗通道是 `(H, W)` 单通道，大气光是 `(3,)`，相除**广播失败**。

两个都是**只有真正跑过才会暴露**的错误。为此加了 `scripts/check_retouch_presets.py` 的实跑冒烟测试：对每条本地预设在一张合成图上真跑一遍，断言输出是合法 JPEG、尺寸一致、像素确实变了。

### 3. 新增资源文件会被漏掉

`scripts/generate_xcodeproj.py` 的资源列表原本写死为 `(Assets.xcassets, pose_library.json)`。新增 `retouch_presets.json` 时如果忘了改，后果是：**App 能编译、能装、能启动，直到运行时读不到预设目录才发现**。

已改成扫描 `LUMI/Resources/` + 扩展名白名单，从结构上消掉这一类。

## 七、隐私边界（与 App 内文案一致）

| 项 | 事实 |
|---|---|
| 默认状态 | **关闭**。不打开总开关，不会发送任何照片。 |
| 画质增强 / 调色 / 人像美化 | 在**你自己的电脑**上算，照片不出本机，不联网。 |
| 生成式改动 | 会发给你**自己配置的**云端服务商。发的是这一张照片与预设参数。 |
| 发送内容 | 只发被精修的那张照片 + 预设 id + 强度 + 文字指令。**不发姿态数据、不发照片库索引、不发其它照片。** |
| 密钥 | **App 里没有任何云端密钥**，密钥只在你电脑的中继脚本里。 |
| 结果存放 | 只在 App 沙盒内，**不写回相册、不覆盖原始照片**。 |
| 删除 | 照片详情页可逐张删除精修副本；设置页可一次删全部。 |

要彻底不用联网：**不打开精修总开关**即可。其余功能（姿势库、照片分析、构图分析）全部本地运行。
