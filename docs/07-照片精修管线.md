# 照片精修管线

本文档说明「照片精修」这个功能**实际是怎么工作的**，以及它**做不到什么**。

---

## 入口在哪

- **首页 → 功能网格 → 「AI 精修与调色」**（主要入口，点进去可以选照片、选预设、看前后对比）
- 照片详情页 → 底部「精修这张照片」/「查看 · 重新精修」
- 设置页 → 「云端精修」（配置总开关与中继地址）

> 首页那张卡是**后来补的**。最初精修只挂在照片详情页的操作按钮和设置页的配置项上，
> 结果是「功能其实存在，但界面上找不到」—— 实测反馈就是
> 「在 LUMI 里并没有看到智能 AI 修图和调色功能」。
> 一个功能只有能被找到才算存在，这一条按这个标准补上。

---

## 一、先说清楚三件做不到的事

这一节的目的是让你在使用前就知道边界，而不是用了之后才发现。

### 1. 「每拍一张照片自动传过来」做不到

**App 无法让相机把照片发过来。** 它没有路径能触发 Z6 II 拍照，也没有路径能接收相机推来的文件。

照片进入 LUMI 的唯一方式是**你从系统相册手动挑选**。所以诚实的说法是：

> **你选完照片导入 LUMI 之后，精修会自动开始。** 不是「相机一拍就自动进来」。

要实现「拍完自己进来」，必须有别的东西先把照片弄到 iPhone 相册里 —— 例如 Nikon SnapBridge 的自动传输，或者 Z6 II 连电脑后由电脑推送。那是 App 之外的事。

### 2. 「实时」做不到

一张 Z6 II 全分辨率照片（约 6000×4000）走完整个流程：

| 环节 | 典型耗时 |
|---|---|
| 上传到电脑 | 局域网内 1–3 秒（24 MP JPEG 约 10–20 MB） |
| 本地算法处理 | 0.3–5 秒（取决于预设，见下表） |
| 云端生成式改动（如果用了） | 额外 5–30 秒 |

**实际是「几秒到几十秒」，不是实时。** 它的定位是「拍完一批、导进来、自动过一遍」，不是「边拍边看」。

### 3. 生成式改动的结果不确定

前三类是确定性算法：**同样的输入永远得到同样的输出**，改动范围也可预期。

「生成式改动」不是 —— 它是让模型**重绘画面内容**。同一张照片、同一句指令，两次结果可能不同；也可能改得超出你的预期。所以这一类必须逐张人工确认。

## 二、架构

```
iPhone (LUMI)                你的电脑 (中继脚本)              云端服务商
     │                              │                            │
     │── POST /retouch ────────────▶│                            │
     │   multipart:                 │                            │
     │     image / preset /         │── 需要生成式时 ───────────▶│
     │     intensity / prompt       │                            │
     │                              │◀──────── 重绘后的图 ────────│
     │◀── image/jpeg ───────────────│                            │
     │    X-Lumi-Provider           │                            │
```

**为什么密钥在电脑上而不在 App 里**：云端密钥一旦编译进 iOS 客户端就等于泄漏 —— 反编译拿字符串是常规操作。App 内的隐私说明写的也是这个做法：「把密钥放在你自己的服务端，客户端只调用你的接口」。

**手机侧只有一条代码路径**：不管是本地算还是调云端，客户端都只做「把照片发给中继、拿回图片」这一件事。这避免了在 Swift 里重写一遍图像算法。

## 三、跑起来

### 依赖

中继需要 `numpy` 和 `opencv-python`。**这两个包装在哪个解释器上，直接决定命令能不能跑起来** —— 这是最容易踩的坑：`python tools/lumi_retouch_server.py` 里的 `python` 是系统 Python，它往往没装这两个包，脚本在开头 `import` 时就会退出，端口不监听，App 侧的表现就是「连不上」。

用项目自带的一键脚本最省事，它会自动挑一个装了依赖的解释器，并在启动前替你验一遍：

```bat
tools\start_retouch_relay.cmd
```

要自己敲命令，就必须用**装了依赖的那个解释器的绝对路径**，先自检再启动：

```bash
# 没有任何输出 = 依赖齐全
"<解释器路径>" -c "import numpy, cv2"

# 缺了就装，装完再用上面那条确认一次
"<解释器路径>" -m pip install opencv-python numpy
```

### 启动

```bash
# 看一眼有哪些预设
"<解释器路径>" tools/lumi_retouch_server.py --list

# 取一次人脸检测模型（只有「面部提亮」需要，约 230 KB）
"<解释器路径>" tools/lumi_retouch_server.py --fetch-face-model

# 启动（只做本地精修，不需要任何密钥）
"<解释器路径>" tools/lumi_retouch_server.py
```

脚本会打印手机侧要填的地址，形如：

```
  手机侧填这个地址（App → 设置 → 云端精修）：
      http://172.20.10.8:8091
```

**先用电脑浏览器打开 `http://127.0.0.1:8091` 自测** —— 状态页会显示本地执行器可用、云端是否已配置、人脸模型是否就绪，以及全部预设列表。

### 在 App 里配置

**设置 → 云端精修 → 开启精修功能 → 填中继地址**。

然后：**照片管理 → 点开一张照片 → 「精修这张照片」**。

### 防火墙

**先确认中继真的在监听，再怀疑防火墙** —— 大多数「连不上」其实是脚本压根没起来（见上面「依赖」一节）：

```bash
netstat -ano -p tcp | findstr "8090 8091"
```

要看到 `0.0.0.0:8091  ...  LISTENING` 这一行才算起来了；没有这一行，问题不在防火墙。

确认在监听、手机仍连不上，才是防火墙的事。Windows 默认会把这类监听当作「公用网络」并拦住：

```powershell
# 管理员 PowerShell
New-NetFirewallRule -DisplayName "LUMI retouch 8091" `
  -Direction Inbound -Protocol TCP -LocalPort 8091 `
  -RemoteAddress LocalSubnet -Action Allow -Profile Any
```

## 四、预设清单（14 条）

### 本地执行（11 条，零密钥，照片不出本机）

| 预设 | 做什么 | 实测耗时（24 MP） |
|---|---|---|
| `enhance.auto` | 按画面统计自动决定降噪/锐化/暗部力度 | ~3.7 s |
| `enhance.denoise` | 保边平滑，**只作用于色度通道**，亮度细节保留 | ~0.3 s |
| `enhance.sharpen` | 亮度通道反锐化掩模 | ~1.3 s |
| `enhance.shadow` | 只抬暗部（权重 `(1-L)³`，纯白处不动） | ~1.7 s |
| `enhance.dehaze` | 暗通道先验去雾 | ~2 s |
| `grade.film` | 抬黑位 + 压高光 + 暗部偏青 | <1 s |
| `grade.clean` | S 形对比曲线 + 提饱和 | <1 s |
| `grade.warm` | 抬红压蓝 + 轻微抬中间调 | <1 s |
| `grade.mono` | 加权转灰 + 对比曲线 | <1 s |
| `portrait.skinSoft` | **肤色掩膜范围内**的保边柔化（保留毛孔与轮廓） | ~2 s |
| `portrait.brightenFace` | YuNet 检测人脸后只提亮脸部；**检测不到人脸就明确报错**，不会整张提亮 | ~2 s |

这些全部是**确定性像素运算**，不是「AI 猜出来的」。同样输入永远同样输出，可复现、可验证。

### 云端执行（3 条，需要你自己配置服务商）

| 预设 | 做什么 |
|---|---|
| `generative.custom` | 用文字描述想要的改动 |
| `generative.removeObject` | 去掉指定物体（在描述里写清去掉什么） |
| `generative.skyReplace` | 替换天空（在描述里写清换成什么） |

**未配置云端时，这三条会被明确拒绝**（HTTP 501，错误码 `provider_not_configured`），**不会返回原图冒充结果**。

## 五、接上你自己的云端服务商

```bash
export LUMI_CLOUD_URL="https://你的服务商/v1/images/edits"
export LUMI_CLOUD_KEY="sk-..."
export LUMI_CLOUD_MODEL="你的模型名"
```

也可以写成命令行参数 `--cloud-url / --cloud-key / --cloud-model`。

密钥只存在于你的电脑上，**不会被打印、不会进这个仓库**。

默认请求形态是 `multipart/form-data` 带 `image` / `prompt` / `model` 字段 —— 这是目前最通用的一种（OpenAI `images/edits` 就是这一形态）。

**换成别的服务商**只需要改 `tools/lumi_retouch_server.py` 里的两处：

- `CloudProvider._build_request` —— 怎么发请求
- `CloudProvider._extract_image` —— 从响应里怎么取图

`_extract_image` 已经支持三种常见形态：直接返回图片、`data[0].b64_json`、`data[0].url`。都不匹配时会明确报错并告诉你要改哪里，而不会猜。

## 五之二、接火山引擎「AI 美颜」（真正的人像精修）

前面第五节的云端执行器是给「生成式改图」留的。**人像精修是另一条线** ——
它用的是火山的专用美化模型，不是通用大模型。这也是为什么它能做到
「磨皮、瘦脸、亮眼、白牙」而人物还是同一个人。

配套脚本：`tools/lumi_volc_beauty.py`。

## 五之三、接阿里云「人脸美颜」（推荐先走这条）

**为什么**：火山的美颜 API 按「创点」计费，创点购买是商务流程（要联系技术支持）；
而阿里云这条**个人实名认证就能自助开通**，按量 0.03 元/次、每月前 100 次免费，
FaceBeauty 还是同步接口 —— 门槛低一个量级。代价是能力窄：只有磨皮/锐化/美白
三个 0~1 参数，**没有瘦脸、美体** —— 所以预设目录里只有 3 条（`ali.natural` /
`ali.clean` / `ali.fresh`），没有做假装的同名预设。

配套脚本：`tools/lumi_aliyun_beauty.py`（启动：`tools/start_aliyun_relay.cmd`，端口 8092）。
App 侧接口与火山适配层**完全相同**，换中继地址即可切换，App 不用改代码。

**已核实**（阿里云官方文档「人脸美颜 FaceBeauty」）：
- endpoint = `facebody.cn-shanghai.aliyuncs.com`，Action = `FaceBeauty`
- 必填参数：`ImageURL`（SDK 文件流直传，**免 OSS**）＋ `Sharp` + `Smooth` + `White`（0~1）
- 输入限制：JPEG/JPG/PNG/BMP，≤3MB，最长边 <2000px（超了脚本用 opencv 自动缩）
- 返回的 `Data.ImageURL` 是**临时地址（30 分钟失效）**——脚本当场取回字节流，App 不受影响
- 计费：调用失败不计费

**开通三步**（全部自助，无商务流程）：
1. 注册阿里云账号并完成**个人实名认证**；
2. 控制台搜「视觉智能开放平台」→ 人脸人体 → **开通**；
3. 创建 AccessKey —— 两个入口任选：
   - **主账号直接创建**（最简单）：<https://ram.console.aliyun.com/manage/ak>
     → 创建 AccessKey → 勾「我确认必须创建 AccessKey」→ 手机验证 →
     **Secret 只显示一次，当场保存**；
   - **RAM 子账号**（官方推荐）：<https://ram.console.aliyun.com/users>
     → 创建用户（勾「使用永久 AccessKey 访问」）→ 用户列表「添加权限」→
     搜索并勾选 `AliyunVIAPIFullAccess`。

```bash
set ALIYUN_AK=你的AccessKey ID
set ALIYUN_SK=你的AccessKey Secret

python tools/lumi_aliyun_beauty.py --selftest      # 离线自检
python tools/lumi_aliyun_beauty.py --presets       # 预设 → 参数映射
python tools/lumi_aliyun_beauty.py --probe --image 某张人像.jpg   # 真实调用一次
python tools/lumi_aliyun_beauty.py --serve --port 8092            # 给 App 用
```

依赖：`pip install alibabacloud_facebody20191230`。要瘦脸的话，后续可另接
`FaceTidyup`（智能瘦脸）接口，脚本里预留了这个扩展点。

### 接口契约（已核实，来源见下）

| 项 | 值 |
| --- | --- |
| Host | `https://kickart.volces.com` |
| 提交 | `POST /openapi/ai_effect/submit` |
| 查询 | `POST /openapi/ai_effect/query` |
| 鉴权 | `Authorization: Bearer {API_KEY}` |
| Content-Type | `application/json` |
| 美颜模板 | `template_id = "245621002"`（美颜 API V2.0 传统修图，支持逐项传参） |
| 一键模板 | `template_id = "245621001"`（AI美颜-Pro，`extra` 固定 `beautyPro_481`） |
| 图片传入 | `payload.resource_list`，元素为 Base64 Data URI（官方建议，比公网 URL 稳） |
| 必填 | `payload.extra.beautyToolConfigKey = "beautyCustom_v1"` |
| 提交返回 | `{"code":0,"message":"success","request_id":"…","data":{"task_id":"…"}}` |

**好消息**：它是 **APIKey（Bearer）**，不是 AK/SK。所以「App 直连」在技术上成立。
但仍然建议加一层你自己的转发 —— 理由见下。

### 为什么还是建议加一层转发

Bearer Key 直接写进 iPhone，等于把凭证交给任何一个能拿到你手机的人；
而且你没有任何办法单独吊销它（只能换 Key，全端一起失效）。
一层转发（云函数或你电脑上的脚本）持有 Key，App 只拿一个随机口令 —— 成本很低，
但它把「手机丢了」和「云账号被刷」这两件事解耦了。

### 三步用起来

```bash
# 1) 拿 API Key：主账号登录控制台（地址见下一节）→ 创作 Agent(Kickart) → API Key → +New
export KICKART_API_KEY=你的key

# 2) 先自检（不需要 key），再真实调一次做校准
python tools/lumi_volc_beauty.py --selftest      # 25 项断言，离线
python tools/lumi_volc_beauty.py --presets       # 看预设 → 火山参数的映射
python tools/lumi_volc_beauty.py --probe --image 某张人像.jpg

# 3) 起转发服务，再把 App 的「中继地址」填成这台机器的地址
python tools/lumi_volc_beauty.py --serve --port 8091 --token 一个随机口令
```

转发服务的接口与 `lumi_retouch_server.py` **完全一致**（`/health`、`/presets`、`/retouch`），
所以 **App 侧不需要任何改动**，把地址填过去就能用。

### 校准状态（2026-10-13 更新）

对照官方「美颜 API V2.0 传统修图接口文档 (APIKey版)」逐项核对后：

**已定稿**（官方文档给了完整 JSON 样例）：
1. `extra` 的分组嵌套 —— 参数分组必须嵌在 `extra.default` 之下，文档明确
   「default 为默认参数组必传」。样例：
   `{"beautyToolConfigKey":"beautyCustom_v1","default":{"beauty":{…},"reshape":{…}}}`
2. `volc.body` 的分组名与参数名 —— 官方「美体」分组是 `bodyshaping`，
   参数是 `slimbody` / `slimwaist` / `leglength`（此前按意译写的
   `body` / `thinbody` / `thinwaist` / `longleg` 是错的，已改）
3. 美颜模板 `template_id = "245621002"`、`beautyToolConfigKey = "beautyCustom_v1"` —— 与官方一致

**仍需真实调用一次确认**（做了容错 + 探针）：
1. 查询接口的入参字段名（按 `task_id` 发，同时容错 `taskId` / `TaskId`）
2. 查询响应里 `result_url` 的路径（做了多路径回退）

`--probe` 会把**原始请求体与原始响应**都打印出来（base64 已截断）。
把响应发我，通常一次就能定稿。

### 关于「创点」与 API Key

- **API Key（自助）**：用**主账号**登录火山引擎控制台 →
  [创作 Agent(Kickart) → API Key](https://console.volcengine.com/kickart/fusion/setting/api-key)
  → `+New` → 命名 → `Create`。拿到一串 Bearer 凭证。
- **创点（商务）**：美颜 API 按「创点」计费，需先购买**支持后付费 API 的创点套餐**
  并开通服务权限 —— 购买链接要**联系火山技术支持获取**，控制台里没有自助入口。
  如果返回 401/403，多半是创点/权限没开 —— 脚本的错误提示里也写了这一点。
- ⚠️ **实测坑（2026-10-13）**：「访问控制 → API 访问密钥」里创建的 **API Key 密钥对**
  （`ak_…` / `sk_…` 一对）**不能直接调 kickart.volces.com 的 OpenAPI** —— 把 Secret 单独、
  `ID:Secret` 拼接、Base64、Basic 等 7 种格式连同标准 V4 签名（服务名试了
  `ic_iam`/`cv`/`kickart`/`mlp`）全部试过，一律返回
  `code 1300 auth failed`。虽然官方「创建火山引擎API Key」文档声称 Kickart 支持该体系
  （权限选「智能创作云」），但实际不认。**调美颜 API 必须用 Kickart 控制台 API Key 页
  签发的单一 Key**（那个页面 `+New` 出来的字符串）。
- 顺带的安全提醒：官方明确要求密钥不得经聊天/截图传递。若已在聊天中发过密钥，
  验证完请到控制台**禁用并轮换**。

## 六、踩过的坑（都写进代码注释了）

### 1. OpenCV 在 Windows 上读不了含中文的绝对路径

`cv2.FaceDetectorYN.create()` 读 ONNX 走的是**窄字符（ANSI）路径**。绝对路径里只要有非 ASCII（例如 `C:\Users\饭饭之叫\...`）就会失败，报 `Can't read ONNX file` —— 而文件明明存在、大小也对。

实测结论：

| 路径形式 | 结果 |
|---|---|
| `tools/models/x.onnx`（相对，纯 ASCII） | ✅ |
| `C:\Users\饭饭之叫\...\tools\models\x.onnx` | ❌ |
| `C:\ProgramData\LUMI\models\x.onnx` | ✅ |

所以脚本写了一条候选路径回退链：**绝对路径 → 相对路径 → 拷到纯 ASCII 目录**。不处理的话，「面部提亮」在中文用户名的机器上必然不可用。

### 2. 暗通道去雾的两个数组错误

- 写了 `max(atmosphere, 1.0)`，而 `atmosphere` 是长度为 3 的数组 —— Python 内置 `max()` 会去比较数组的真值，直接抛 `ValueError`。
- 修掉之后立刻撞上第二个：暗通道是 `(H, W)` 单通道，大气光是 `(3,)`，相除**广播失败**。

两个都是**只有真正跑过才会暴露**的错误。为此加了 `scripts/check_retouch_presets.py` 的实跑冒烟测试：对每条本地预设在一张合成图上真跑一遍，断言输出是合法 JPEG、尺寸一致、像素确实变了。

### 3. 新增资源文件会被漏掉

`scripts/generate_xcodeproj.py` 的资源列表原本写死为 `(Assets.xcassets, pose_library.json)`。新增 `retouch_presets.json` 时如果忘了改，后果是：**App 能编译、能装、能启动，直到运行时读不到预设目录才发现**。

已改成扫描 `LUMI/Resources/` + 扩展名白名单，从结构上消掉这一类。

## 七、隐私边界（与 App 内文案一致）

| 项 | 事实 |
|---|---|
| 默认状态 | **关闭**。不打开总开关，不会发送任何照片。 |
| 画质增强 / 调色 / 人像美化 | 在**你自己的电脑**上算，照片不出本机，不联网。 |
| 生成式改动 | 会发给你**自己配置的**云端服务商。发的是这一张照片与预设参数。 |
| 发送内容 | 只发被精修的那张照片 + 预设 id + 强度 + 文字指令。**不发姿态数据、不发照片库索引、不发其它照片。** |
| 密钥 | **App 里没有任何云端密钥**，密钥只在你电脑的中继脚本里。 |
| 结果存放 | 只在 App 沙盒内，**不写回相册、不覆盖原始照片**。 |
| 删除 | 照片详情页可逐张删除精修副本；设置页可一次删全部。 |

要彻底不用联网：**不打开精修总开关**即可。其余功能（姿势库、照片分析、构图分析）全部本地运行。
