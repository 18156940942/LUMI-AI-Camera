# 硬件连接与监看指南（Nikon Z6 II → iPhone 15 Pro）

本文档的目标是让你**在半小时内**把 Z6 II 的画面弄到 iPhone 上，并且知道每一步为什么这么做、出问题该查哪里。

---

## 1. 先明确一件事：为什么不能直接插线

你可能已经试过，或者正准备试：**把 HDMI 采集卡插到 iPhone 15 Pro 的 USB-C 口上**。

**这不会成功，而且不是配置问题。**

- Apple DTS 工程师在开发者论坛的明确答复：*"it is expected that iPhone 15 Pro does not support external cameras"*、*"only iPad supports external cameras"*；
- WWDC 2023 场次《Support external cameras in your iPadOS app》的原话：*"iPads with USB-C connectors support external cameras"*；
- `AVCaptureDevice.DeviceType.external` 这个 API 符号从 iOS 17 开始存在，但它的用途是给 iPadOS 用的。在 iPhone 上构造 `AVCaptureDevice.DiscoverySession` 请求 `.external` 类型，返回的一定是空数组。

**iPhone 上的 USB-C 只是接口形状相同，USB 控制器的能力集不同。** 这一点没有任何绕过方式（至少在公开 API 范围内没有）。

LUMI 在这一点上的做法是：当你在 iPhone 上选择「外接 UVC 采集设备」时，App **不会**让你插上线等一个永远不来的设备，而是**立刻**告诉你原因，并列出可行的替代路径。这是刻意的设计，不是「功能缺失」。

## 2. 三条真实可用的路径

| | 路径 A：网络中继 | 路径 B：UVC 直连 | 路径 C：内置摄像头 |
|---|---|---|---|
| **链路** | 相机 → 采集卡 → 电脑 → Wi-Fi → iPhone | 相机 → 采集卡 → iPad（USB-C） | iPhone 自身镜头 |
| **iPhone 15 Pro** | ✅ 可用 | ❌ 系统不支持 | ✅ 可用 |
| **iPad（USB-C）** | ✅ 可用 | ✅ 可用 | ✅ 可用 |
| **延迟** | 约 150–400 ms | 约 1 帧（最低） | 最低 |
| **需要什么** | 一台电脑 + 同一个 Wi-Fi | 一台 USB-C 的 iPad | 无 |
| **画质上限** | 1080p30（取决于 Wi-Fi） | 1080p60 | 手机镜头本身 |
| **用途** | **iPhone 上的主力方案** | iPad 上的最佳方案 | **仅自测 / 备用，不是相机监看** |

> 路径 C 是重要但容易被误解的一条。它显示的是 **iPhone 自己的画面**，不是 Z6 II 的画面。App 里把它明确标注为「自测/备用，非相机监看」，绝对不会让它冒充相机监看。它的真实用途是：验证监看界面的参考线、缩放、全屏、AI 分析功能是否正常工作，而不用把整套硬件接起来。

**本文档主要讲路径 A**，因为那是你在 iPhone 上唯一能用的真实监看路径。

## 3. 路径 A 需要的硬件

```
┌──────────────┐   HDMI 线    ┌─────────────┐   USB 线   ┌──────────────┐
│  Nikon Z6 II │─────────────▶│  UVC 采集卡  │───────────▶│   电脑        │
│  HDMI OUT    │  (mini-HDMI  │  (免驱)      │            │  跑中继脚本   │
│  (Type C)    │   转标准 HDMI)│             │            │              │
└──────────────┘              └─────────────┘            └───────┬──────┘
                                                                 │
                                                          Wi-Fi / 局域网
                                                                 │
                                                          ┌──────▼──────┐
                                                          │  iPhone 15  │
                                                          │  Pro        │
                                                          └─────────────┘
```

### 3.1 HDMI 线

Z6 II 上的是 **mini-HDMI（Type C）**，不是标准 HDMI，也不是 micro-HDMI。你需要一根 **mini-HDMI 转标准 HDMI** 的线（或一个转接头）。

⚠️ 这里最容易出错的地方：**micro-HDMI 和 mini-HDMI 长得很像但不一样**。买之前确认接口形状。Z6 II 用的是 mini-HDMI。

### 3.2 UVC 采集卡

**关键要求：必须是免驱的 UVC（USB Video Class）设备。**

免驱意味着插上电脑后，系统直接把它识别为一个「USB 摄像头」，不需要装厂商驱动。市面上的 HDMI 采集卡基本都是 UVC 的，但要确认两点：

- **支持 1080p60 输入**：便宜的卡片很多只支持 1080p30 或 4K30。Z6 II 输出 1080p 是最稳的配置。
- **不要买「带环出但主控很弱」的廉价卡**：这类卡会在高分辨率下大量丢帧，表现为画面卡顿。判断方法是插上电脑后用 OBS 预览，看有没有明显掉帧。

推荐的经典型号（都属于免驱 UVC）：Elgato Cam Link 4K、Magewell USB Capture HDMI Gen 2、或者国产的「USB 3.0 HDMI 采集卡 / 视频采集棒」。

### 3.3 USB 线

**必须是数据线，不能是纯充电线。** 这个坑极其常见：很多 USB-C 线只接了电源针脚。如果你插上电脑后设备列表里没有新摄像头，先换一根线试试。

### 3.4 电脑

任何能跑 Python 的电脑都行（Windows / macOS / Linux）。不需要独显，因为 MJPEG 编码是 CPU 的 JPEG 编码，1080p30 的负载很低。

### 3.5 网络

**手机和电脑必须在同一个局域网（同一个 Wi-Fi）。** 并且：

- 那个 Wi-Fi **不能开启「AP 隔离 / 客户端隔离」**（很多公共 Wi-Fi 和访客网络会开，开了之后设备之间无法互相访问）；
- 有条件就用 **5 GHz**。1080p30 的 MJPEG 需要 15–40 Mbps 的稳定带宽，2.4 GHz 在室内经常不够；
- 电脑最好用**网线**接路由器，把 Wi-Fi 带宽全部留给手机。

## 4. 相机端设置（Z6 II 菜单）

这几项是**必须**的，否则画面会带相机的对焦框和参数叠加，或者监看会中途断掉。

| 菜单路径 | 设置为 | 为什么 |
|---|---|---|
| HDMI → 输出分辨率 | **Auto** | 让采集卡协商它实际支持的分辨率。强制指定可能出现握手失败 |
| HDMI → 输出显示尺寸 | **100%** | 只有 100% 才是干净的全画幅输出；其他值是裁切或缩放 |
| HDMI → 实时取景信息显示 | **关闭** | 开启的话画面上会带相机的对焦框、参数、直方图等叠加，采集卡会一起采进去 |
| HDMI → 外部录像控制 | 关闭 | 避免误触相机开始录制 |
| 自定义设定 → 待机定时器 | **无限** | 相机待机后 HDMI 输出会掉，监看中断。这是长时间拍摄必设项 |
| 自定义设定 → 空插槽释放快门 | 按需 | 与监看无关，但现场拍摄建议开启 |

**Z6 II 不支持 HDMI 输出的情况**（遇到这些场景不要怀疑是采集卡的问题）：

- 1080/120p、1080/100p
- 慢动作模式
- Movie 模式下同时连接 Camera Control Pro 2

以上来自 Nikon 官方的「通过 HDMI 输出未压缩视频」说明文档。遇到这些情况时 HDMI 会黑屏或无输出，这是相机固件的行为。

**机身侧的准备**：

- 用满电或外接电源（HDMI 输出会明显增加耗电，一块电池大约撑 1.5–2 小时）；
- 关掉「自动关机」或设最长时间；
- 如果需要长时间拍摄，用假电池（假电池 + DC 电源）最省心。

## 5. 电脑端：启动中继脚本

### 5.1 安装依赖

```bash
pip install opencv-python
```

只需要 OpenCV 一个依赖（用于读取采集卡的帧并编码为 JPEG）。

### 5.2 确认采集设备序号

```bash
python tools/lumi_mjpeg_server.py --list
```

输出形如：

```
正在扫描视频采集设备（会逐个尝试打开，可能需要几秒钟）……

  [0] 可用   1920×1080 @ 30.0 fps
  [1] 设备存在但读不到画面（可能被其它程序占用）

共 1 个可用设备。启动示例：
  python tools/lumi_mjpeg_server.py --device 0 --width 1920 --height 1080 --fps 30
```

> ⚠️ 如果显示「设备存在但读不到画面」，最常见的原因是 **OBS / 相机厂商的软件 / 上一次没退干净的 python 进程**还占着这个设备。采集卡同一时刻只能被一个程序打开。

### 5.3 启动中继

```bash
python tools/lumi_mjpeg_server.py --device 0 --width 1920 --height 1080 --fps 30
```

会打印：

```
LUMI 相机中继 · MJPEG over HTTP
========================================================
  · 采集设备已打开：0
  · 实际采集格式：1920×1080 @ 30.0 fps（请求 1920×1080 @ 30）

  本机验证（先在电脑上确认画面正常）：
    http://127.0.0.1:8090/
    单帧快照 http://127.0.0.1:8090/snapshot

  在 iPhone 的 LUMI App 里填这个地址：
    http://192.168.1.10:8090/stream

  提醒：
    · 手机与电脑必须在同一个 Wi-Fi（且该 Wi-Fi 未开启 AP 隔离）
    · Windows 首次运行会弹出防火墙提示，需要勾选「专用网络」允许
    ...
```

**Windows 首次运行一定要在防火墙弹窗里勾选「专用网络」并点「允许访问」。** 不点的话手机永远连不上。

### 5.4 先在电脑上验证

**这一步不要跳过。** 用电脑浏览器打开 `http://127.0.0.1:8090/`，你应该能看到实时画面和下面这些状态：

- 分辨率（是否与你请求的一致）
- 实测帧率（应该接近 30）
- 已发送帧数（在持续增长）
- 丢弃帧数（少量正常，持续大量增长说明解码跟不上）

如果这里正常，说明「相机 → 采集卡 → 电脑 → 编码 → HTTP」这一整段都没问题，剩下的只是网络问题。

如果这里就不正常，**先别去看 iPhone**，去查第 7 节的故障排查表。

### 5.5 全部参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--list` | — | 列出所有采集设备后退出 |
| `--device N` | `0` | 设备序号，也支持设备路径（Linux 上是 `/dev/video0`） |
| `--width` / `--height` | `1920` / `1080` | 请求的采集分辨率。**实际以设备支持为准**，脚本会打印实际生效的值 |
| `--fps` | `30` | 采集与推送帧率 |
| `--quality` | `75` | JPEG 质量 1–100。75 是清晰度与带宽的平衡点；想更清晰调到 85（带宽约增加 50%） |
| `--port` | `8090` | 监听端口 |
| `--host` | `0.0.0.0` | 监听地址。默认允许局域网访问；只想本机测试可以设 `127.0.0.1` |
| `--fourcc` | `MJPG` | 像素格式。某些采集卡在 MJPG 下不稳，可以换 `--fourcc YUY2` |
| `--no-preview` | 关 | 不打印控制台实时统计 |

**关于分辨率的现实建议**：1080p30 是甜点。如果你想更省带宽（比如 Wi-Fi 环境一般），用 `--width 1280 --height 720`，MJPEG 带宽大约降到 1/3，而对「看构图和姿势」这个用途来说完全够用。

## 6. iPhone 端：填入地址开始监看

1. 打开 LUMI → 底部 **实时监看** 标签；
2. 展开 **输入** 面板；
3. 选择 **网络中继流**（另外两个选项会显示「本机不可用」及其原因）；
4. 填入地址。格式是 `http://<电脑局域网IP>:<端口>/stream`；
5. 点 **开始监看**。

> **重要设计说明**：LUMI **不会自动开始监看**。视频输入涉及相机、采集卡与局域网访问，必须由你显式点击才启动。这是刻意的 —— 你不希望打开 App 就默默占用摄像头和网络。

### 6.1 应该看到什么

- 画面填满监看区（按 16:9 适配，两侧或上下留黑边）；
- 顶部状态条显示：输入类型、分辨率、实测帧率、帧龄、丢弃帧数；
- 默认叠加三分线（可在「参考线」里关掉）；
- 点一下画面可以**双击全屏**，全屏时会自动切换到横屏并常亮屏幕。

### 6.2 延迟的预期

局域网 MJPEG 的实测延迟大约 **150–400 ms**（端到端，从相机传感器到 iPhone 显示）。这个量级意味着：

- **看构图、看姿势、看表情**：完全够用，这是 LUMI 的主要用途；
- **抓精确时机按下快门**：不够用。但因为**快门是由你在相机上按的**，这个限制不影响实际拍摄流程。

想要更低延迟，只有两条路：用 iPad 走 UVC 直连（约 1 帧），或者接受现实。USB-C 的 iPhone 做不到，这不是软件能解决的问题。

### 6.3 网络模式的选择

LUMI 支持两种中继协议：

| 模式 | 延迟 | 带宽 | 什么时候用 |
|---|---|---|---|
| **MJPEG**（默认） | 150–400 ms | 15–40 Mbps @1080p30 | 绝大多数情况 |
| HLS | 1–3 s 起 | 3–8 Mbps | 局域网带宽实在不够时，但延迟会大到没法用来判断姿势 |

脚本只提供 MJPEG。如果你确实需要 HLS（例如中继要通过弱网段），可以用 ffmpeg 把采集卡转成 HLS：

```bash
ffmpeg -f dshow -video_size 1920x1080 -framerate 30 -i video="你的采集卡名称" \
  -c:v libx264 -preset ultrafast -tune zerolatency -g 30 -hls_time 1 -hls_list_size 3 \
  -f hls /path/to/stream.m3u8
```

然后在 LUMI 里把模式切到 HLS，地址填 `http://<IP>:<端口>/stream.m3u8`。

## 7. 故障排查对照表

按「从相机往手机」的顺序查，这样最快定位。

### 7.1 电脑上就看不到画面

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `--list` 一个设备都没有 | HDMI 线没插紧 / 插错接口 | 确认插的是相机上的 **HDMI OUT**（mini-HDMI Type C），相机开机 |
| | USB 线是纯充电线 | **换一根数据线**。这是最高频的原因 |
| | 采集卡没被系统识别 | Windows：设备管理器里看「照相机」下有没有新设备；macOS：关于本机 → 系统报告 → 相机 |
| `--list` 显示「设备存在但读不到画面」 | 被其他程序占用 | 关掉 OBS、相机厂商软件、以及残留的 python 进程（Windows 用任务管理器找 `python.exe`） |
| | 采集卡需要更高供电 | 换到电脑的另一个 USB 口，或用带供电的 USB Hub |
| 能打开但画面全黑 | 相机 HDMI 输出没启用 | 相机上翻到 HDMI 设置，确认「输出分辨率」不是「关闭」 |
| | 相机在播放模式 | 把相机拨到拍照/录像模式，HDMI 只在实时取景时输出 |
| | 用了相机不支持输出的模式 | 检查是否是 1080/120p、慢动作、或 Movie + Camera Control Pro 2 |
| 画面是彩条 / 花屏 | HDMI 握手失败 | 拔插 HDMI 线；把相机 HDMI 输出分辨率改成 Auto；换一根质量好点的 HDMI 线 |
| 画面带了相机的对焦框和参数 | 「实时取景信息显示」没关 | 相机菜单：HDMI → 实时取景信息显示 → **关闭** |
| 画面比例不对/被裁切 | HDMI 输出显示尺寸不是 100% | 改成 **100%** |
| 画面卡顿、控制台丢弃帧数持续增长 | JPEG 编码跟不上 / USB 带宽不足 | 降分辨率到 720p：`--width 1280 --height 720`；换 USB 3.0 口 |
| | `--fourcc MJPG` 下采集卡不稳 | 换 `--fourcc YUY2` 试试 |

### 7.2 电脑上正常，iPhone 连不上

| 现象 | 可能原因 | 处理 |
|---|---|---|
| LUMI 提示「无法连接中继服务」 | Windows 防火墙拦了 | 首次运行时的防火墙弹窗要勾「专用网络」并允许；已忽略的话去「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」手动加 python.exe |
| | 手机和电脑不在同一 Wi-Fi | iPhone 设置 → 无线局域网，确认 SSID 与电脑一致。**注意手机关掉「私有 Wi-Fi 地址」有时也会有影响** |
| | Wi-Fi 开了 AP 隔离 | 家用路由器一般不开，但访客网络/公共网络常开。换一个 SSID 或用手机热点试试（见下） |
| | IP 地址填错了 | 用脚本打印的那个地址。如果你有多个网卡（比如同时有以太网和 Wi-Fi），脚本会列出多个，挑与手机同一网段的那个 |
| | 电脑上有 VPN 或代理在跑 | 关掉 VPN 再试。VPN 会改变路由表，导致局域网内的请求被送到隧道里 |
| 能连上但画面一直转圈 | MJPEG 流被中间设备缓冲 | 检查是否有代理；确认用的是 5 GHz Wi-Fi |
| 画面几秒后停止更新 | 相机 HDMI 掉线（待机定时器） | 相机：待机定时器设为**无限** |
| | Wi-Fi 瞬时抖动 | LUMI 会显示「视频流已停止约 N 秒」，点「重新连接」即可 |

**一个很好用的诊断技巧**：用手机浏览器（Safari）直接打开 `http://<电脑IP>:8090/`。

- 如果 Safari 也不显示画面 → 是网络层问题（防火墙 / 网段 / AP 隔离）；
- 如果 Safari 能显示但 LUMI 不能 → 是 App 层问题，把这个现象告诉我。

**没有路由器的应急方案**：用 iPhone 的个人热点让电脑连上去。这样两者一定在同一个网段，且没有 AP 隔离。缺点是热点通常跑在 2.4 GHz，带宽可能不够 1080p，建议同时把分辨率降到 720p。

### 7.3 能监看，但 AI 分析有问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 姿势指导一直说「未检测到人物」 | 被摄者太小 / 逆光 / 肢体被大面积遮挡 | 让被摄者占画面更大比例；避免强逆光；避免手臂抱在身前遮住躯干 |
| 骨架抖得厉害 | 关键点置信度低 | 这是 Vision 的检测特性。LUMI 会按置信度降低关键点的绘制不透明度，并在置信度不足时停止给角度结论 —— 这是刻意设计，不是 bug |
| 提示「关键点识别不稳定，暂不给角度结论」 | 综合置信度 < 30% 或有效关键点 < 8 个 | 改善光照与取景。**这条提示是设计目标之一**：宁可不说，也不给错的角度 |
| 构图分析说「未检测到人物」 | 同上 | 同上。没有人物时 LUMI 不会给出任何构图结论 |
| 曝光辅助一直显示固定的读数 | 这是完全正常的 | 三种输入都拿不到相机机身的测光值。LUMI 给的是**画面像素的亮度分布**，不是相机测光。界面上明确标注了这一点 |

## 8. 路径 B：iPad + UVC 直连（延迟最低）

如果你手上（或者以后）有一台 **带 USB-C 的 iPad**，这条路径体验明显更好，因为它是原生的：

- 延迟约 1 帧，肉眼基本感知不到；
- 不需要电脑、不需要 Wi-Fi、不需要中继脚本；
- 画质上限更高（1080p60）。

操作：

1. HDMI 线从 Z6 II 接到 UVC 采集卡的 HDMI IN；
2. 采集卡的 USB 插 iPad 的 USB-C 口（如果采集卡供电需求高，用带供电的 USB-C Hub）；
3. 打开 LUMI → 实时监看 → 输入 → **外接 UVC 采集设备**；
4. 点「开始监看」。

LUMI 在 iPad 上会自动把这一项标为**可用**（`VideoInputCapability.supportsExternalCamera` 会返回 `true`），首页的能力卡片也会跟着变。

如果 iPad 上提示「没有检测到外接 UVC 采集设备」，排查顺序是：

1. 采集卡是不是免驱 UVC 型号（有厂商专有驱动的不是）；
2. 用数据线而不是充电线；
3. 换一个 USB-C 口，或用带供电的 Hub；
4. iPad 是否 iPadOS 17 或更高（`AVCaptureDevice.DeviceType.external` 需要 17+）；
5. App 里的「设置 → 输入设备状态」会显示系统实际枚举到的外接设备数量，这个数字是 0 就说明系统层面没认到。

## 9. 现场拍摄的实用建议

**设备摆放**

- 电脑放在相机附近，用较短的高质量 HDMI 线。mini-HDMI 接口比较脆弱，长线容易被绊到；
- 如果 HDMI 线必须超过 3 米，用带信号放大的主动式 HDMI 线，否则可能握手失败或闪屏；
- iPhone 用三脚架或磁吸支架固定在相机旁边（或者交给助手拿着），解放你的双手。

**续航与散热**

- **相机**：HDMI 输出很耗电，一块电池约 1.5–2 小时。长时间拍摄用假电池。
- **电脑**：插电源，别让它在拍摄中途休眠（Windows：电源选项 → 从不休眠；macOS：`caffeinate`）。
- **iPhone**：开监看 + AI 分析时耗电明显。LUMI 有「保持屏幕常亮」选项（全屏监看时自动开启），但这个选项本身就是耗电的。建议接充电宝。
- **发热**：同时开实时姿势指导 + 构图分析会明显升温。**LUMI 默认把这两个都关掉了**（`livePoseEnabled = false`、`liveCompositionEnabled = false`），需要时再打开。如果 iPhone 开始降频或提示过热，先关掉这两个。

**建议的工作流**

1. 架好相机与主机位，先只开监看，确认画面与构图；
2. 在姿势助手里选定场景与风格，把姿势步骤念给模特（或者把 iPhone 转过去给模特看）；
3. 摆好姿势后，临时打开**实时姿势指导**，看肩线/头部/手臂的具体角度提示，微调；
4. 微调完关掉姿势指导（省电），开始正式拍；
5. 一批拍完后，用照片管理导入挑选出来的片子做筛选。

**关于姿势助手的实际用法**

姿势助手输出的是**分步指令**，不是一句「自然一点」。例如「身体向左侧旋转约 30°；转头 70° 看向画面右侧；视线落点：越过肩膀看向远处树梢；靠近镜头一侧的肩膀压低约 3cm；一侧膝盖微屈，另一侧腿保持直立……」—— 这种程度的描述是**可以直接念给模特听的**。这是这个功能存在的全部意义。
